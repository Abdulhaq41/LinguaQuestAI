# Статус и ограничения

Версия 0.1.0. Разработана из пустого checkout; удалённый репозиторий на момент начала не имел веток/коммитов. Исходники находятся в `/workspace/LinguaQuestAI` и загружены в GitHub `Abdulhaq41/LinguaQuestAI`, ветка `main`. Публичный сервис Render и публикация облачной среды пока не выполнялись.

## Проверенные локальные возможности

Онбординг, первый бесплатный урок, ответы/объяснения, сохранение/восстановление результатов, тарифы и API-ограничения. Есть полноценные DB-модели и миграции, код бота, интеграция Stars и AI, защищённая админка, базовая игровая экономика и небольшая библиотека учебного контента. Данные индивидуальны, подтверждённые результаты переживают обновление страницы. Подтверждения внешних сервисов в тестах синтетические и не выдаются за настоящие платежи.

## Что блокирует публичный запуск

| Требование | Статус |

| Реальная Stars-оплата, продление, отмена, возврат | Адаптеры и транзакции проверены тестами; нужны реальный бот и испытания в поддерживаемой Telegram-среде |
| Текстовый AI через реальный API | Адаптер проверен с транспортными подменами; нужен ключ и live-проверка качества/модерации |

| Аналитика | Реальные события, DAU/WAU/MAU, пользователи, активные подписки, Stars и оценка AI; нет полноценных cohort retention, LTV, churn и unit economics-панелей |

## Операционные ограничения

- AI-запросы сериализуются DB-блокировкой бюджета: разумно для малого старта, не для большого параллелизма. Следующий шаг масштабирования — атомарные резервирования бюджета и отдельная очередь.
- Proxy rate limit и счётчик в процессе — защита первого уровня. За NAT/IP общего proxy лимит может затронуть нескольких пользователей; production требует настройки доверенной цепочки proxy и распределённого лимитера.
- Worker рассчитан на один scheduler. Доставка Telegram-уведомлений как минимум однократная: при обрыве между отправкой и фиксацией возможен повтор. Финансовая обработка отделена и идемпотентна.
- При неизвестном результате refund-запроса (сбой после успешного ответа до DB commit) нужна сверка с Telegram; имеется обработчик `refunded_payment`, но отдельного полного сверщика `getStarTransactions` пока нет. Не трактовать отсутствие webhook как доказательство отсутствия оплаты.
- Удаление аккаунта сохраняет платежи и их связи в псевдонимизированной форме. Сроки хранения должен утвердить владелец. Резервные копии удаляются по отдельной политике.
- Реферальный бонус — косметические монеты, не бесплатные дни. Возврат отзывает доступный бонус; купленные до возврата косметические предметы не отбираются автоматически. Нужны ручной контроль злоупотреблений и правила программы.
- Колонки/таблицы, зарезервированные для расширения (например simulation_progress), не означают готовность соответствующих расширенных возможностей.

Не включать продажи на основании одного зелёного unit-теста. Обязательны реальный checkout, повтор доставки, продление, отмена, возврат, два окна оплаты, перезапуск, неуспешная оплата и сопоставление с реестром Telegram. Неподключённые интеграции и перечисленные продуктовые пробелы не считаются завершёнными.
