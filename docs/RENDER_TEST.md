# Тестовый бот на Render

Используется уже созданный @Linguaquesttest_bot. Создавать основной бот или покупать отдельный домен для этой проверки не нужно. Render предоставляет адрес вида поддомена onrender.com после создания сервиса. Текущее тестовое размещение: https://linguaquest-test.onrender.com. 9 ноября 2026 владелец получил `telegram=ready` и подтвердил работу приложения. Прямой доступ к этому домену из облачной среды ограничен сетевой политикой; это подтверждение владельца, не независимая live-проверка агентом.

## Что подготовлено

`render.yaml` описывает один Docker web service и PostgreSQL. В одном контейнере находятся API и собранная Mini App; запросы идут на тот же origin, cookie Secure. База сохраняет прогресс независимо от файлов web-контейнера. Перед запуском применяются миграции. Строка подключения от PaaS преобразуется к установленному драйверу psycopg v3.

WEBAPP_URL берётся из RENDER_EXTERNAL_URL. WEBHOOK_SECRET генерируется хостингом. Если генератор использует base64 с символами, запрещёнными Telegram, приложение детерминированно преобразует достаточно длинное значение в SHA-256 hex. Это одинаково применяется при регистрации webhook и при проверке входящих запросов; менять значение вручную в Render не требуется. После запуска API отдельная задача проверяет username через getMe, настраивает webhook без удаления pending updates, кнопку Mini App и команды. Секреты не попадают в Dockerfile, blueprint, Git или сообщения о настройке.

Функция настройки включена только при AUTO_CONFIGURE_BOT=true. Состояние доступно через `/api/deployment/status`: not_configured, pending, ready или failed. При ошибке возвращаются только безопасные коды причины, этап, номер попытки и HTTP-статус; данные запросов, токен и исходный текст ошибки провайдера не возвращаются. Наличие переменной BOT_TOKEN само по себе не означает ready.

## Действия владельца

1. Войдите в https://dashboard.render.com через свой аккаунт. Не присылайте пароль или код входа в чат.
2. Код с render.yaml загружен в GitHub-репозиторий Abdulhaq41/LinguaQuestAI, ветка main. Подключите этот репозиторий к Render через свой GitHub-аккаунт.
3. Создайте Blueprint по своему репозиторию и нужной ветке. Шаблон запрашивает планы free для теста. Доступность, сроки действия базы, ограничения простоя и актуальная цена должны проверяться в интерфейсе Render перед созданием ресурсов. Никакой платный сервис агент автоматически не создавал.
4. В защищённое поле BOT_TOKEN **в Render** вставьте токен тестового бота. Не вставляйте его в обычные сообщения, название сервиса или репозиторий. BOT_USERNAME уже задан как Linguaquesttest_bot.
5. Дождитесь сборки и запуска. При успехе /api/health отвечает ok, а /api/deployment/status — telegram=ready. Если webhook ещё не доступен снаружи, настройка повторяется с ограниченным числом попыток; журнал не печатает токен.
6. Откройте @Linguaquesttest_bot, отправьте /start, откройте приложение. Пройдите цель и бесплатный урок, обновите приложение и убедитесь, что результат сохранён.
7. Для ссылок `?startapp=ref_...` отдельно укажите Main Mini App URL в BotFather после получения реального адреса. Кнопка меню и кнопки в /start настраиваются программно.

Для уже созданного сервиса повторно создавать Blueprint и базу не нужно. Обновление админки: [docs/ADMIN.md](ADMIN.md).

## Ограничения тестового размещения

- COMMERCE_ENABLED=false, AI_ENABLED=false, ENABLE_DEV_AUTH=false. Настоящих списаний Stars и выдачи фиктивных платежей здесь нет. Первый тест — запуск, Telegram auth, урок и серверный прогресс.
- Учебный контент и незавершённые возможности остаются описанными в STATUS.md. Этот deployment template не делает продукт готовым к продаже.
- Worker уведомлений/повторных возвратов не входит в минимальный blueprint. Перед включением реальных продаж нужен постоянно работающий worker, поддержка и live-проверки платежей; для production есть docker-compose.yml. Не включайте коммерцию на этом минимальном тестовом варианте без этих работ.
- Доступность free-планов, их холодный старт, квоты и срок хранения free PostgreSQL определяет Render. Автоматического перехода на платный план этот репозиторий не выполняет.
- После изменения домена или смены бота нужно перепроверить WEBAPP_URL, username, webhook и Main Mini App. Один токен используется только для одного активного размещения; polling одновременно с webhook не запускается.
- Подключение Telegram подтверждено владельцем. Подарки и админка проверены локально; после обновления Render их нужно открыть в настоящем Telegram WebView.

## Диагностика неуспешного подключения

Вместо одного `failed` статус теперь содержит `step` и `error`. Если Render предоставляет RENDER_GIT_COMMIT, при неуспехе также показывается сокращённая `revision`. Это позволяет проверить, что запущена последняя версия. При `ready` ответ остаётся коротким.

- `invalid_bot_token` / HTTP 401: Telegram отклонил токен. Проверьте действующий ключ только в защищённом поле Render.
- `invalid_bot_token_format` или `bot_api_not_found` / HTTP 404: проверьте полноту и формат скопированного ключа; причина 404 сама по себе не доказывает отзыв ключа.
- `bot_username_mismatch`: ключ относится к другому username; существующий бот автоматически не перенастраивается.
- `invalid_webhook_secret`: Telegram не принял формат секрета. Проверьте revision и наличие исправления нормализации.
- `webhook_dns_error`, `webhook_tls_error`, `webhook_rejected`: отказ регистрации публичного webhook; проверьте настоящий HTTPS URL сервиса.
- `request_timeout`, `network_error`, `telegram_unavailable`: ошибки связи, ограниченные повторы.
- `rate_limited`: соблюдается полученный Retry-After.
- `auto_configuration_disabled`, `missing_bot_token`: соответствующая настройка отсутствует или отключена.
- `local_api_not_ready`: локальный API не стал доступен для настройки.
- `internal_setup_error`: непредусмотренная внутренняя ошибка; её текст и секретные данные намеренно не публикуются.

Ошибки ключа и конфигурации завершают настройку сразу. Временные отказы повторяются максимум пять раз. В общий журнал попадают только метод, безопасный код и номер попытки.
