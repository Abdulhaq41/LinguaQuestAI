# Расходы и масштабирование

Это модель допущений, не коммерческое предложение и не гарантированная маржа.

- Небольшой VPS (2 GB RAM) с API, PostgreSQL, worker и reverse proxy: ориентир $5–15/месяц, зависит от провайдера и региона. Offsite backups, домен, мониторинг, трафик и налоги отдельно. При нагрузке нужны фактические замеры.
- Уроки и графика предсозданы, LLM не вызывается на каждый ответ. Обычные уроки работают без AI-затрат.
- Текстовый запрос ограничен 1500 символами ввода и 500 токенами ответа. Учитываются фактические prompt/completion tokens, стоимость оценивается по переменным цен. История в prompt не отправляется.
- Пример **непроверенных ценовых допущений**: $0.40/1M input и $1.60/1M output. Для 600 input + 200 output оценка одного ответа — $0.00056. 100 таких ответов в день: около $1.68 за 30 дней, плюс возможные расходы модерации/внешнего сервиса. Перед запуском заменить на актуальные цены выбранного провайдера и модели.
- Дневной лимит приложения 100000 учтённых токенов. Перед запросом резервируется верхняя оценка 4096; остаток бюджета может не использоваться полностью. Это не жёсткий лимит фактического счёта провайдера: таймаут после генерации может быть тарифицирован без доступной usage-статистики. Настройте отдельные project spending limits и оповещения у провайдера.
- AI_ENABLED=false — ручной kill switch. После 5 provider failures за 120с система прекращает новые вызовы на короткий период. Повторы по UUID не генерируют новый успешный ответ.
- Голос не реализован и не оценён. Обещанные 150/500 минут не должны продаваться до STT/TTS integration, серверного резервирования минут и проверки реальной себестоимости.
- Stars: START 89/30д, PRO 149/30д и ULTRA 299/30д (последние не продаются). **Нет гарантированного курса вывода Stars**. Для маржи владелец должен задать собственную подтверждённую оценку net receipts с учётом платформы, региона, возвратов, налогов и задержки вывода.

Формулы: `AI_cost = input_tokens * input_price/1e6 + output_tokens * output_price/1e6`; `estimated_margin = estimated_net_receipts - AI_cost - allocated_infra - other_costs`. LTV не рассчитывается без модели удержания. Процент маржи и эквивалент Stars в деньгах в продукте не выдумываются.

Сначала измеряйте time-to-first-lesson, demo completion, paywall conversion, подтверждённые оплаты, удержание и реальные токены. Следующая инфраструктурная ступень: queue-based AI reservation вместо глобальной DB-блокировки, Redis rate limiting, PostgreSQL backups/replica и CDN для графики. Сохраняйте финансовую идемпотентность при любом количестве процессов.
